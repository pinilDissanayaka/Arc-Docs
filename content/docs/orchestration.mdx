## Overview

Graph Orchestration in the Arc Framework provides a powerful way to build complex multi-agent workflows as Directed Acyclic Graphs (DAGs). It enables you to create sophisticated agent systems where agents act as nodes in a graph, with explicit control over execution flow, dependencies, and routing logic.

The graph orchestration system consists of two main components:
- **GraphOrchestrator**: Low-level orchestrator for building and managing agent workflow graphs
- **GraphWorkflow**: High-level workflow interface with enhanced validation and execution tracking

## Core Components

### GraphOrchestrator

`GraphOrchestrator` is the foundational class that manages the construction and execution of multi-agent workflow graphs. It provides:

- Node management (agents, teams, supervisors)
- Edge definition for workflow routing
- Cycle detection to prevent infinite loops
- State persistence with checkpointers
- Hierarchical graph building utilities

**Location**: `arc/core/orchestrator.py`

### GraphWorkflow

`GraphWorkflow` provides a higher-level abstraction over `GraphOrchestrator` with workflow-specific features:

- Simplified API for common workflow patterns
- Entry and exit point management
- Validation and error handling
- Execution result aggregation
- Graph structure visualization

**Location**: `arc/workflows/graph_workflow.py`

### State Management

All graph workflows use the `State` class for managing workflow state:

```python
class State(MessagesState):
    messages: List[AnyMessage]  # Conversation history
    next: str                   # Next node to visit
    full_plan: str             # Execution plan
    context: Dict[str, Any]    # Additional context
    metadata: Dict[str, Any]   # Tracking metadata
    rl_metadata: Dict[str, Any] # RL-specific data
```

**Location**: `arc/core/state.py`

### Supervisor

The `Supervisor` class uses LLM-based decision making to route requests between team members:

```python
supervisor = Supervisor(
    llm=llm,
    members=["team1", "team2", "team3"],
    system_prompt="Custom routing logic..."
)
```

**Location**: `arc/core/supervisor.py`

## Basic Usage

### Creating a Simple Graph Workflow

```python
from arc.workflows import GraphWorkflow
from arc.agents.team_builder import TeamBuilder
from langchain_openai import ChatOpenAI

# Initialize LLM
llm = ChatOpenAI(model="gpt-4")

# Create workflow
workflow = GraphWorkflow(
    name="DataPipeline",
    max_iterations=20,
    enable_cycle_detection=True
)

# Create agents
fetcher = TeamBuilder("fetcher").with_llm(llm).build()
processor = TeamBuilder("processor").with_llm(llm).build()
validator = TeamBuilder("validator").with_llm(llm).build()

# Add nodes to workflow
workflow.add_node("fetch", fetcher)
workflow.add_node("process", processor)
workflow.add_node("validate", validator)

# Define execution flow
workflow.add_edge("fetch", "process")
workflow.add_edge("process", "validate")

# Set entry and exit points
workflow.set_entry_point("fetch")
workflow.set_exit_point("validate")

# Compile and run
compiled = workflow.compile()
result = workflow.run("Process the latest data")

print(result["output"])
```

### Using GraphOrchestrator Directly

For more control, use `GraphOrchestrator` directly:

```python
from arc.core.orchestrator import GraphOrchestrator
from arc.core.supervisor import Supervisor
from arc.nodes import CoordinatorNode, PlannerNode, ResponseGeneratorNode

# Create orchestrator
orchestrator = GraphOrchestrator(
    max_iterations=20,
    enable_cycle_detection=True
)

# Add coordinator and planner
coordinator = CoordinatorNode(llm=llm)
planner = PlannerNode(llm=llm)
orchestrator.add_node("coordinator", coordinator)
orchestrator.add_node("planner", planner)

# Add teams
orchestrator.add_team(math_team)
orchestrator.add_team(research_team)

# Add supervisor
supervisor = Supervisor(
    llm=llm,
    members=["math_team", "research_team"]
)
orchestrator.set_supervisor(supervisor)

# Add response generator
generator = ResponseGeneratorNode(llm=llm)
orchestrator.add_node("generator", generator)

# Define edges
orchestrator.add_edge("start", "coordinator")
orchestrator.add_edge("coordinator", "planner")
orchestrator.add_edge("planner", "supervisor")
orchestrator.add_edge("supervisor", "generator")
orchestrator.add_edge("generator", "end")

# Compile
graph = orchestrator.compile()

# Execute
result = graph.invoke({"messages": [("user", "Solve this problem")]})
```

## Advanced Patterns

### Hierarchical Graph

Use the convenience method for building hierarchical agent systems:

```python
from arc.core.orchestrator import GraphOrchestrator
from arc.core.supervisor import MainSupervisor
from arc.nodes import CoordinatorNode, PlannerNode, ResponseGeneratorNode

# Create components
orchestrator = GraphOrchestrator()
coordinator = CoordinatorNode(llm=llm)
planner = PlannerNode(llm=llm)
supervisor = MainSupervisor(llm=llm, members=["team1", "team2"])
generator = ResponseGeneratorNode(llm=llm)

# Build hierarchical graph
graph = orchestrator.build_hierarchical_graph(
    coordinator=coordinator,
    planner=planner,
    supervisor=supervisor,
    teams=[team1, team2],
    generator=generator
)

# Execute
result = graph.invoke({"messages": [("user", "Your task here")]})
```

### Parallel Execution Paths

Create workflows with parallel execution branches:

```python
workflow = GraphWorkflow(name="ParallelPipeline")

# Add parallel processing nodes
workflow.add_node("fetch", fetcher_agent)
workflow.add_node("process_a", processor_a)
workflow.add_node("process_b", processor_b)
workflow.add_node("merge", merger_agent)

# Create parallel paths
workflow.add_edge("fetch", "process_a")
workflow.add_edge("fetch", "process_b")
workflow.add_edge("process_a", "merge")
workflow.add_edge("process_b", "merge")

workflow.set_entry_point("fetch")
workflow.set_exit_point("merge")

compiled = workflow.compile()
```

### Conditional Routing with Supervisor

Use a supervisor for dynamic routing based on task requirements:

```python
from arc.core.supervisor import Supervisor

# Create specialized teams
data_team = TeamBuilder("data_team").with_llm(llm).with_description(
    "Handles data processing and analysis"
).build()

reporting_team = TeamBuilder("reporting_team").with_llm(llm).with_description(
    "Creates reports and visualizations"
).build()

# Create supervisor with custom prompt
supervisor = Supervisor(
    llm=llm,
    members=["data_team", "reporting_team"],
    system_prompt="""
    Route tasks based on requirements:
    - Data processing, analysis, transformations -> data_team
    - Report creation, formatting, visualization -> reporting_team
    - When all work is complete -> FINISH
    """
)

# Build graph
orchestrator = GraphOrchestrator()
orchestrator.add_team(data_team)
orchestrator.add_team(reporting_team)
orchestrator.set_supervisor(supervisor, name="supervisor")

# Define flow
orchestrator.add_edge("start", "supervisor")
# Supervisor will route to teams or END automatically

graph = orchestrator.compile()
```

### Multi-Stage Pipeline

Build complex multi-stage workflows:

```python
workflow = GraphWorkflow(name="BuildPipeline")

# Define stages
stages = [
    ("lint", linter_agent),
    ("test", tester_agent),
    ("build", builder_agent),
    ("package", packager_agent),
    ("deploy", deployer_agent)
]

# Add all stages
for stage_name, agent in stages:
    workflow.add_node(stage_name, agent)

# Chain stages sequentially
for i in range(len(stages) - 1):
    current_stage = stages[i][0]
    next_stage = stages[i + 1][0]
    workflow.add_edge(current_stage, next_stage)

workflow.set_entry_point(stages[0][0])
workflow.set_exit_point(stages[-1][0])

compiled = workflow.compile()
result = workflow.run("Deploy version 2.0")
```

## Configuration Options

### GraphOrchestrator Parameters

```python
orchestrator = GraphOrchestrator(
    state_class=State,              # Custom state class (default: State)
    checkpointer=MemorySaver(),     # State persistence (default: MemorySaver)
    max_iterations=20,              # Max workflow iterations (default: 20)
    enable_cycle_detection=True     # Prevent cycles (default: True)
)
```

### GraphWorkflow Parameters

```python
workflow = GraphWorkflow(
    name="MyWorkflow",              # Workflow identifier (required)
    state_class=State,              # Custom state class (default: State)
    max_iterations=20,              # Max iterations (default: 20)
    enable_cycle_detection=True,    # Cycle detection (default: True)
    description="Description"       # Workflow description (optional)
)
```

### Execution Configuration

```python
# Configure thread-based execution
config = {
    "configurable": {
        "thread_id": "conversation_1"
    }
}

# Execute with configuration
result = graph.invoke({"messages": [("user", "Your task")]}, config=config)

# Stream execution
for chunk in graph.stream(
    {"messages": [("user", "Your task")]},
    config,
    stream_mode="values"
):
    print(chunk["messages"][-1].content)
```

## API Reference

### GraphOrchestrator

#### Methods

**`add_node(name: str, node: Callable | BaseNode) -> GraphOrchestrator`**
- Add a node to the graph
- Returns self for method chaining
- Location: `orchestrator.py:73`

**`add_team(team: BaseTeam) -> GraphOrchestrator`**
- Add a team as a node
- Automatically builds the team
- Returns self for method chaining
- Location: `orchestrator.py:95`

**`set_supervisor(supervisor: Supervisor, name: str = "supervisor") -> GraphOrchestrator`**
- Set the supervisor for routing
- Returns self for method chaining
- Location: `orchestrator.py:119`

**`add_edge(from_node: str, to_node: str) -> GraphOrchestrator`**
- Add directed edge between nodes
- Supports special nodes: "start", "end"
- Returns self for method chaining
- Location: `orchestrator.py:147`

**`set_entry_point(node_name: str) -> GraphOrchestrator`**
- Set the graph entry point
- Returns self for method chaining
- Location: `orchestrator.py:189`

**`compile() -> Any`**
- Compile the graph for execution
- Returns compiled graph
- Location: `orchestrator.py:204`

**`build_hierarchical_graph(...) -> Any`**
- Build complete hierarchical graph
- Convenience method for common pattern
- Returns compiled graph
- Location: `orchestrator.py:219`

**`validate_graph() -> None`**
- Validate graph structure
- Raises ValidationError if invalid
- Location: `orchestrator.py:344`

### GraphWorkflow

## Complete Example

Here's a complete example showing a hierarchical multi-agent system with graph orchestration:

```python
from arc.config import load_config
from arc.agents.team_builder import TeamBuilder
from arc.core.orchestrator import GraphOrchestrator
from arc.core.supervisor import MainSupervisor
from arc.nodes import CoordinatorNode, PlannerNode, ResponseGeneratorNode
from langchain_core.tools import tool

# Define tools
@tool
def calculate_sum(numbers: str) -> str:
    """Calculate the sum of comma-separated numbers."""
    nums = [float(n.strip()) for n in numbers.split(',')]
    return f"The sum is {sum(nums)}"

@tool
def format_report(title: str, content: str) -> str:
    """Format content as a professional report."""
    return f"\n=== {title.upper()} ===\n\n{content}\n\n" + "=" * 50

# Load configuration
config = load_config("config.yml")
llm = config.get_llm()

# Create specialized teams
math_team = TeamBuilder("math_team") \
    .with_llm(llm) \
    .with_tools([calculate_sum]) \
    .with_prompt("You are a math specialist. Use calculate_sum for additions.") \
    .with_description("Handles mathematical calculations") \
    .build()

report_team = TeamBuilder("report_team") \
    .with_llm(llm) \
    .with_tools([format_report]) \
    .with_prompt("You are a report writer. Create professional reports.") \
    .with_description("Handles report formatting") \
    .build()

# Create orchestration components
supervisor = MainSupervisor(
    llm=llm,
    members=["math_team", "report_team"]
)

coordinator = CoordinatorNode(llm=llm)
planner = PlannerNode(llm=llm)
generator = ResponseGeneratorNode(llm=llm)

# Build hierarchical graph
orchestrator = GraphOrchestrator()
graph = orchestrator.build_hierarchical_graph(
    coordinator=coordinator,
    planner=planner,
    supervisor=supervisor,
    teams=[math_team, report_team],
    generator=generator
)

# Execute workflow
config = {"configurable": {"thread_id": "session_1"}}

for chunk in graph.stream(
    {"messages": ("user", "Calculate 2 + 897 - 9 and format as a report")},
    config,
    stream_mode="values"
):
    if chunk["messages"]:
        print(chunk["messages"][-1].content)
```

## Best Practices

### 1. Use Descriptive Node Names

```python
# Good
workflow.add_node("validate_input", validator)
workflow.add_node("process_data", processor)
workflow.add_node("generate_output", generator)

# Avoid
workflow.add_node("node1", validator)
workflow.add_node("n2", processor)
```

### 2. Enable Cycle Detection

Always enable cycle detection unless you have a specific reason not to:

```python
workflow = GraphWorkflow(
    name="MyWorkflow",
    enable_cycle_detection=True  # Prevents infinite loops
)
```

### 3. Set Appropriate Iteration Limits

```python
# For simple workflows
workflow = GraphWorkflow(name="Simple", max_iterations=10)

# For complex multi-stage workflows
workflow = GraphWorkflow(name="Complex", max_iterations=50)
```

### 4. Validate Before Execution

```python
# Compile validates automatically
workflow.compile()

# Or validate explicitly
orchestrator.validate_graph()
```

### 5. Use Supervisors for Dynamic Routing

For workflows where routing decisions depend on task content, use a supervisor instead of static edges:

```python
# Static routing (less flexible)
workflow.add_edge("coordinator", "team1")

# Dynamic routing (more flexible)
supervisor = Supervisor(llm=llm, members=["team1", "team2", "team3"])
orchestrator.set_supervisor(supervisor)
```

### 6. Leverage Method Chaining

```python
workflow = GraphWorkflow(name="Pipeline") \
    .add_node("fetch", fetcher) \
    .add_node("process", processor) \
    .add_node("validate", validator) \
    .add_edge("fetch", "process") \
    .add_edge("process", "validate") \
    .set_entry_point("fetch") \
    .set_exit_point("validate")
```

### 7. Use Appropriate State Classes

For custom workflows, extend the State class:

```python
from arc.core.state import State

class CustomState(State):
    processing_stage: str = ""
    error_count: int = 0
    custom_data: Dict[str, Any] = {}

workflow = GraphWorkflow(
    name="Custom",
    state_class=CustomState
)
```

## Error Handling

The graph orchestration system includes built-in error handling:

```python
from arc.exceptions import (
    GraphError,
    GraphCycleError,
    MaxIterationsExceededError,
    ValidationError
)

try:
    workflow.add_edge("node_a", "node_b")
    workflow.add_edge("node_b", "node_a")  # Creates cycle
    workflow.compile()
except GraphCycleError as e:
    print(f"Cycle detected: {e}")
    print(f"Details: {e.details}")

try:
    graph = workflow.compile()
    result = graph.invoke({"messages": [("user", "task")]})
except MaxIterationsExceededError as e:
    print(f"Workflow exceeded maximum iterations: {e}")
```
