## Introduction

Nodes are the fundamental building blocks of the Arc Framework's workflow graph. Each node represents a discrete processing unit that performs a specific task and can transition to other nodes based on its execution results. The framework provides three pre-built node types that form a complete hierarchical workflow:

1. **CoordinatorNode** - Front-line user interaction and task triage
2. **PlannerNode** - Task decomposition and execution planning
3. **ResponseGeneratorNode** - Final response synthesis and formatting


## Architecture

### Node Workflow

```
User Input → CoordinatorNode → PlannerNode → Supervisor → Teams → ResponseGeneratorNode → User
```

### Node Lifecycle

1. **Initialization** - Node is created with required configuration
2. **Execution** - Node's `execute()` method is called with current state
3. **Processing** - Node performs its specific task
4. **Routing** - Node returns a Command with next destination
5. **State Update** - State is updated with node's outputs

### State Management

All nodes operate on a shared state dictionary with the following structure:

```python
{
    "messages": List[Message],  # Conversation history
    "full_plan": str,           # Complete execution plan (optional)
    "metadata": Dict[str, Any], # Additional metadata
    # ... other custom fields
}
```

## Base Node Class

All nodes inherit from the `BaseNode` abstract base class.

### Class Definition

```python
from arc.core.base import BaseNode

class BaseNode(ABC):
    """
    Abstract base class for all nodes in the framework.

    Attributes:
        name: Unique identifier for the node
        description: Human-readable description of the node's purpose
    """

    def __init__(self, name: str, description: str = ""):
        self.name = name
        self.description = description
        self._logger = logging.getLogger(f"{self.__class__.__name__}.{name}")

    @abstractmethod
    def execute(self, state: Dict[str, Any]) -> Command:
        """Execute the node's logic."""
        pass

    def __call__(self, state: Dict[str, Any]) -> Command:
        """Make the node callable."""
        return self.execute(state)
```

### Key Methods

#### `execute(state: Dict[str, Any]) -> Command`

The core method that must be implemented by all node subclasses.

- **Args**:
  - `state`: Current workflow state dictionary
- **Returns**:
  - `Command`: LangGraph Command object with updates and routing
- **Raises**:
  - `NodeExecutionError`: If execution fails
  - `ValidationError`: If state is invalid

#### `__call__(state: Dict[str, Any]) -> Command`

Makes the node callable directly. Logs execution and delegates to `execute()`.

## CoordinatorNode

The coordinator acts as the front-line agent that handles user interaction and decides whether to hand off to the planner or end the conversation.

### Purpose

- Initial user interaction and greeting
- Understanding user requests
- Determining task complexity
- Routing decisions (planner vs. end)
- Handling simple queries directly

### Class Definition

```python
from arc.nodes import CoordinatorNode

coordinator = CoordinatorNode(
    llm=llm,                              # Required: Language model
    system_prompt=None,                    # Optional: Custom prompt
    handoff_keyword="handoff_to_planner",  # Optional: Trigger keyword
    name="coordinator"                     # Optional: Node name
)
```

### Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `llm` | `BaseChatModel` | Required | Language model for coordination |
| `system_prompt` | `str \| None` | `None` | Custom system prompt (uses default if None) |
| `handoff_keyword` | `str` | `"handoff_to_planner"` | Keyword that triggers planner handoff |
| `name` | `str` | `"coordinator"` | Unique identifier for the node |

### Default Behavior

The coordinator uses an intelligent default prompt that:

1. Greets users warmly
2. Handles simple greetings and small talk
3. Delegates complex tasks to planner
4. Maintains conversational and professional tone
5. Asks clarifying questions when needed

### Routing Logic

```python
# Decision flow:
if "handoff_to_planner" in response.content:
    goto = "planner"  # Route to planner
else:
    goto = END        # End conversation
```

### Methods

#### `execute(state: Dict[str, Any]) -> Command[Literal["planner", "__end__"]]`

Executes coordinator logic with automatic retry and timeout.

**Returns:**
```python
Command(
    update={
        "messages": [HumanMessage(content=response, name="coordinator")]
    },
    goto="planner" | END
)
```

#### `set_prompt(prompt: str) -> None`

Updates the system prompt dynamically.

```python
coordinator.set_prompt("You are a specialized coordinator for...")
```

#### `set_handoff_keyword(keyword: str) -> None`

Changes the handoff detection keyword.

```python
coordinator.set_handoff_keyword("ROUTE_TO_PLANNER")
```

### Location

**File**: `arc/nodes/coordinator.py`

### Example Usage

```python
from langchain_openai import ChatOpenAI
from arc.nodes import CoordinatorNode

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.7)

# Basic usage
coordinator = CoordinatorNode(llm=llm)

# Custom configuration
coordinator = CoordinatorNode(
    llm=llm,
    system_prompt="You are a technical support coordinator...",
    handoff_keyword="ESCALATE",
    name="support_coordinator"
)

# Use in graph
state = {"messages": [{"role": "user", "content": "Hello!"}]}
result = coordinator(state)
```

### Error Handling

The coordinator includes built-in error handling with:

- Automatic retry (up to 2 attempts with 30s timeout)
- State validation
- Response validation
- Detailed error logging

```python
try:
    result = coordinator.execute(state)
except ValidationError as e:
    # Handle invalid state
    print(f"Invalid state: {e.details}")
except NodeExecutionError as e:
    # Handle execution failure
    print(f"Coordinator failed: {e.details}")
```

## PlannerNode

The planner creates comprehensive execution plans for complex tasks, breaking them down into steps and determining which teams to involve.

### Purpose

- Analyze complex user requests
- Decompose tasks into executable steps
- Identify required teams/agents
- Create structured JSON plans
- Consider dependencies and sequencing

### Class Definition

```python
from arc.nodes import PlannerNode

planner = PlannerNode(
    llm=llm,               # Required: Language model
    system_prompt=None,    # Optional: Custom prompt
    validate_json=True,    # Optional: Enable JSON validation
    name="planner"         # Optional: Node name
)
```

### Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `llm` | `BaseChatModel` | Required | Language model for planning |
| `system_prompt` | `str \| None` | `None` | Custom system prompt (appended to default) |
| `validate_json` | `bool` | `True` | Whether to validate plan as valid JSON |
| `name` | `str` | `"planner"` | Unique identifier for the node |

### Plan Structure

The planner generates structured JSON plans with the following format:

```json
{
    "task": "High-level task description",
    "steps": [
        {
            "step": 1,
            "description": "Detailed step description",
            "assigned_team": "team_name",
            "dependencies": [],
            "tool_selection": ["tool1", "tool2"],
            "expected_output": "What this step should produce"
        }
    ],
    "success_criteria": "How to know when task is complete"
}
```

### Methods

#### `execute(state: Dict[str, Any]) -> Command[Literal["supervisor", "__end__"]]`

Generates and validates execution plan.

**Returns:**
```python
Command(
    update={
        "messages": [HumanMessage(content=json_plan, name="planner")],
        "full_plan": json_plan
    },
    goto="supervisor" | END  # END if validation fails
)
```

#### `set_prompt(prompt: str) -> None`

Updates the system prompt.

```python
planner.set_prompt("Focus on security considerations...")
```

#### `set_validation(validate: bool) -> None`

Enables or disables JSON validation.

```python
planner.set_validation(False)  # Disable validation
```

### Internal Methods

#### `_clean_json_response(response: str) -> str`

Removes markdown code fences and formatting from JSON.

```python
# Input: "```json\n{...}\n```"
# Output: "{...}"
```

#### `_validate_plan(plan: str) -> bool`

Validates that the plan is valid JSON.

```python
try:
    json.loads(plan)
    return True
except json.JSONDecodeError:
    return False
```

### Location

**File**: `arc/nodes/planner.py`

### Example Usage

```python
from langchain_openai import ChatOpenAI
from arc.nodes import PlannerNode

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.5)

# Basic usage
planner = PlannerNode(llm=llm)

# Custom configuration
planner = PlannerNode(
    llm=llm,
    system_prompt="Additional context about available teams...",
    validate_json=True,
    name="task_planner"
)

# Use in graph
state = {
    "messages": [
        {"role": "user", "content": "Analyze security vulnerabilities"}
    ]
}
result = planner(state)

# Access plan
full_plan = result.update["full_plan"]
print(full_plan)
```

### Streaming Support

The planner uses streaming for better performance:

```python

```

## ResponseGeneratorNode

The generator synthesizes final responses from team outputs, creating coherent, user-friendly responses.

### Purpose

- Analyze complete conversation history
- Review outputs from all teams
- Synthesize information coherently
- Format responses professionally
- Ensure accuracy and completeness

### Class Definition

```python
from arc.nodes import ResponseGeneratorNode

generator = ResponseGeneratorNode(
    llm=llm,              # Required: Language model
    system_prompt=None,   # Optional: Custom prompt
    name="response_generator"  # Optional: Node name
)
```

### Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `llm` | `BaseChatModel` | Required | Language model for generation |
| `system_prompt` | `str \| None` | `None` | Custom system prompt (uses default if None) |
| `name` | `str` | `"response_generator"` | Unique identifier for the node |

### Quality Standards

The generator follows these quality standards:

- **Accuracy**: All information must be correct
- **Completeness**: Address all aspects of the query
- **Clarity**: Easy to understand
- **Relevance**: Focus on what the user needs
- **Actionability**: Provide next steps when appropriate

### Methods

#### `execute(state: Dict[str, Any]) -> Command[Literal["__end__"]]`

Generates final response and ends workflow.

**Returns:**
```python
Command(
    update={
        "messages": [HumanMessage(content=response, name="response_generator")]
    },
    goto=END  # Always ends the workflow
)
```

#### `set_prompt(prompt: str) -> None`

Updates the system prompt.

```python
generator.set_prompt("Focus on technical accuracy and citations...")
```

### Location

**File**: `arc/nodes/generator.py`

### Example Usage


## Creating Custom Nodes

You can create custom nodes by extending the `BaseNode` class.

### Basic Template

```python
from typing import Literal, Dict, Any
from arc.core.base import BaseNode
from langgraph.types import Command
from langgraph.graph import END

class CustomNode(BaseNode):
    """
    Custom node for specialized processing.
    """

    def __init__(self, llm, name: str = "custom"):
        super().__init__(name=name, description="Custom processing")
        self.llm = llm
        self._logger.info(f"CustomNode '{name}' initialized")

    def execute(self, state: Dict[str, Any]) -> Command[Literal["next_node", "__end__"]]:
        """
        Execute custom logic.
        """
        try:
            self._logger.info(f"{self.name} processing...")

            # Your custom logic here
            result = self.process(state)

            # Determine routing
            goto = "next_node" if result.needs_more else END

            return Command(
                update={
                    "messages": [{"role": "assistant", "content": result.content}],
                    "custom_field": result.data
                },
                goto=goto
            )
        except Exception as e:
            self._logger.error(f"Execution failed: {str(e)}")
            raise

    def process(self, state: Dict[str, Any]) -> Any:
        """Custom processing logic."""
        # Implement your logic
        pass
```

### Advanced Example

```python
from arc.core.base import BaseNode
from arc.exceptions import NodeExecutionError, ValidationError
from arc.utils.retry import retry_with_timeout

class DataProcessorNode(BaseNode):
    """
    Node that processes and validates data.
    """

    def __init__(self, llm, validators=None, name="processor"):
        super().__init__(name=name, description="Processes data")
        self.llm = llm
        self.validators = validators or []

    @retry_with_timeout(max_retries=3, timeout=60.0)
    def execute(self, state: Dict[str, Any]) -> Command:
        # Validate input
        if not self._validate_input(state):
            raise ValidationError("Invalid input data")

        # Process
        try:
            processed = self._process_data(state)
        except Exception as e:
            raise NodeExecutionError(f"Processing failed: {e}")

        return Command(
            update={"processed_data": processed},
            goto="next_step"
        )

    def _validate_input(self, state: Dict[str, Any]) -> bool:
        """Validate input data."""
        for validator in self.validators:
            if not validator(state):
                return False
        return True

    def _process_data(self, state: Dict[str, Any]) -> Dict[str, Any]:
        """Process the data."""
        # Your processing logic
        return {}
```

## Best Practices

### 1. Logging

Use the built-in logger for all node operations:

```python
self._logger.info("Starting process...")
self._logger.debug(f"Details: {details}")
self._logger.warning("Potential issue detected")
self._logger.error(f"Error occurred: {error}")
```

### 2. Error Handling

Always validate inputs and handle errors gracefully:

```python
def execute(self, state: Dict[str, Any]) -> Command:
    try:
        # Validate state
        if "messages" not in state:
            raise ValidationError("Missing messages")

        # Execute logic
        result = self._process(state)

        return Command(update=result, goto="next")

    except ValidationError:
        raise  # Re-raise validation errors
    except Exception as e:
        raise NodeExecutionError(f"Node failed: {e}")
```

### 3. State Updates

Always return proper Command objects with updates:

```python
# Good
return Command(
    update={
        "messages": [new_message],
        "metadata": {"timestamp": time.time()}
    },
    goto="next_node"
)

# Bad - missing update
return Command(goto="next_node")
```

### 4. Routing

Use clear routing logic with proper type hints:

```python
def execute(self, state: Dict[str, Any]) -> Command[Literal["option_a", "option_b", "__end__"]]:
    if condition_a:
        goto = "option_a"
    elif condition_b:
        goto = "option_b"
    else:
        goto = END

    return Command(update={...}, goto=goto)
```

### 5. Retry Logic

Use retry decorators for unreliable operations:

```python
from arc.utils.retry import retry_with_timeout

@retry_with_timeout(max_retries=3, timeout=30.0, backoff_factor=2.0)
def execute(self, state: Dict[str, Any]) -> Command:
    # This will retry up to 3 times with exponential backoff
    return self.llm.invoke(state["messages"])
```

### 6. Testing

Write unit tests for your custom nodes:

```python
import pytest
from arc.exceptions import ValidationError

def test_custom_node():
    node = CustomNode(llm=mock_llm)
    state = {"messages": [{"role": "user", "content": "test"}]}

    result = node.execute(state)

    assert "messages" in result.update
    assert result.goto in ["next", END]

def test_validation_error():
    node = CustomNode(llm=mock_llm)

    with pytest.raises(ValidationError):
        node.execute({})  # Invalid state
```

## Error Handling

### Built-in Exceptions

The framework provides several exception types:

```python
from arc.exceptions import (
    NodeExecutionError,    # Node execution failed
    ValidationError,       # Invalid input/state
    LLMTimeoutError,       # LLM call timed out
    ConfigurationError     # Configuration issue
)
```

### Error Handling Pattern

```python
def execute(self, state: Dict[str, Any]) -> Command:
    try:
        # Validate
        self._validate_state(state)

        # Execute
        result = self._process(state)

        # Return
        return Command(update=result, goto="next")

    except ValidationError as e:
        self._logger.error(f"Validation failed: {e.details}")
        raise
    except LLMTimeoutError as e:
        self._logger.error(f"LLM timeout: {e}")
        raise
    except Exception as e:
        self._logger.error(f"Unexpected error: {e}")
        raise NodeExecutionError(
            f"Node {self.name} failed",
            details={"error": str(e)}
        )
```

### Retry Configuration

Configure retry behavior for resilience:

```python
@retry_with_timeout(
    max_retries=3,        # Number of retry attempts
    timeout=30.0,         # Timeout per attempt (seconds)
    backoff_factor=2.0    # Exponential backoff multiplier
)
def execute(self, state: Dict[str, Any]) -> Command:
    # Automatically retries on failure with exponential backoff
    pass
```

## Examples

### Complete Workflow Example

```python
from langchain_openai import ChatOpenAI
from arc.nodes import CoordinatorNode, PlannerNode, ResponseGeneratorNode
from arc.core import GraphOrchestrator, Supervisor

# Initialize LLMs
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.7)
coordinator_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# Create nodes
coordinator = CoordinatorNode(coordinator_llm)
planner = PlannerNode(llm)
generator = ResponseGeneratorNode(llm)

# Create supervisor (routes to teams)
supervisor = Supervisor(llm, members=["research_team", "analysis_team"])

# Build graph
orchestrator = GraphOrchestrator()
orchestrator.add_node("coordinator", coordinator)
orchestrator.add_node("planner", planner)
orchestrator.set_supervisor(supervisor)
orchestrator.add_node("response_generator", generator)
orchestrator.set_entry_point("coordinator")

# Compile and run
graph = orchestrator.compile()
result = graph.invoke({
    "messages": [{"role": "user", "content": "Analyze market trends"}]
})

print(result["messages"][-1].content)
```

### Custom Node Example

```python
from arc.core.base import BaseNode
from langgraph.types import Command
from langgraph.graph import END

class ValidationNode(BaseNode):
    """Validates user input before processing."""

    def __init__(self, rules, name="validator"):
        super().__init__(name=name, description="Validates input")
        self.rules = rules

    def execute(self, state: Dict[str, Any]) -> Command:
        self._logger.info("Validating user input...")

        messages = state.get("messages", [])
        last_message = messages[-1]["content"]

        # Check validation rules
        is_valid = all(rule(last_message) for rule in self.rules)

        if is_valid:
            self._logger.info("Input validated successfully")
            goto = "planner"
        else:
            self._logger.warning("Input validation failed")
            goto = END

        return Command(
            update={
                "messages": [{
                    "role": "assistant",
                    "content": "Valid" if is_valid else "Invalid input"
                }],
                "validated": is_valid
            },
            goto=goto
        )

# Usage
validator = ValidationNode(
    rules=[
        lambda x: len(x) > 10,
        lambda x: any(c.isalpha() for c in x)
    ]
)

orchestrator.add_node("validator", validator)
```

### Conditional Routing Example

```python
class RouterNode(BaseNode):
    """Routes based on content analysis."""

    def execute(self, state: Dict[str, Any]) -> Command[Literal["technical", "general", "__end__"]]:
        content = state["messages"][-1]["content"]

        # Analyze content
        if self._is_technical(content):
            goto = "technical"
            self._logger.info("Routing to technical team")
        elif self._is_general(content):
            goto = "general"
            self._logger.info("Routing to general team")
        else:
            goto = END
            self._logger.info("Unable to route, ending")

        return Command(
            update={"routing_decision": goto},
            goto=goto
        )

    def _is_technical(self, text: str) -> bool:
        keywords = ["code", "function", "error", "bug"]
        return any(kw in text.lower() for kw in keywords)

    def _is_general(self, text: str) -> bool:
        keywords = ["question", "help", "explain"]
        return any(kw in text.lower() for kw in keywords)
```
