# Arc Overview

**Arc** is a professional framework, designed for building complex AI agent systems with advanced orchestration patterns. With under 20 lines of code, you can create sophisticated multi-agent workflows with coordinator-planner-supervisor architecture, reinforcement learning, and multiple workflow patterns.

Arc provides pre-built agent architectures, workflow patterns, and intelligent routing to help you build production-ready agent systems quickly and efficiently.

We recommend Arc Framework when you need hierarchical agent coordination, advanced reasoning patterns, or complex multi-agent orchestration. Arc excels at tasks requiring multiple specialized agents working together, intelligent tool selection with RL, and dynamic workflow management.

## Install

```bash
pip install -r requirements.txt
```

## Create an Agent System

```python
from arc import (
    Config,
    GraphOrchestrator,
    Supervisor,
    CoordinatorNode,
    PlannerNode,
    ResponseGeneratorNode,
    TeamBuilder
)

# Load configuration
config = Config.from_yaml("config.yml")
llm = config.get_llm()

# Create a specialized team with tools
@tool
def search_database(query: str) -> str:
    """Search the database for information."""
    return f"Results for: {query}"

research_team = (TeamBuilder("research_team")
    .with_llm(llm)
    .with_tools([search_database])
    .with_prompt("You are a research assistant.")
    .build())

# Build hierarchical graph
orchestrator = GraphOrchestrator()
orchestrator.add_node("coordinator", CoordinatorNode(llm))
orchestrator.add_node("planner", PlannerNode(llm))
orchestrator.add_team(research_team)
orchestrator.set_supervisor(Supervisor(llm, members=["research_team"]))
orchestrator.add_node("generator", ResponseGeneratorNode(llm))
orchestrator.set_entry_point("coordinator")

# Compile and run
graph = orchestrator.compile()
result = graph.invoke({
    "messages": [{"role": "user", "content": "Research AI frameworks"}]
})

print(result["messages"][-1].content)
```

## Architecture

Arc Framework follows a hierarchical architecture that routes user queries through multiple layers:

```
User Input → Coordinator → Planner → Supervisor → Teams → Generator → Response
```

### Coordinator Layer
The coordinator handles initial user interaction and makes routing decisions. Simple queries get direct responses, while complex tasks are forwarded to the planner.

### Planning Layer
The planner decomposes complex tasks into execution plans, identifies required teams, and creates a structured workflow in JSON format.

### Supervision Layer
The supervisor routes tasks to appropriate teams, manages workflow coordination, and handles dynamic team selection based on the plan.

### Team Layer
Teams are specialized agents with specific tools and capabilities. Each team has its own supervisor for internal routing and coordination.

### Generation Layer
The response generator synthesizes outputs from all teams and creates coherent, complete final responses.

## Workflow Patterns

Arc Framework provides multiple workflow patterns for different orchestration needs:

### Sequential Workflow
Linear chain execution where agents process tasks one after another.

```python
from arc.workflows import SequentialWorkflow

workflow = SequentialWorkflow(agents=[agent1, agent2, agent3])
result = workflow.run(task)
```

### Concurrent Workflow
Parallel execution where multiple agents work simultaneously.

```python
from arc.workflows import ConcurrentWorkflow

workflow = ConcurrentWorkflow(agents=[agent1, agent2, agent3])
result = workflow.run(task)
```

### Mixture of Agents
Expert synthesis where multiple agents propose solutions and an aggregator combines them.

```python
from arc.workflows import MixtureOfAgents

workflow = MixtureOfAgents(
    agents=[expert1, expert2, expert3],
    aggregator_agent=aggregator
)
result = workflow.run(task)
```

### Forest Swarm
Dynamic tree selection where the system chooses the best agent tree for each task.

```python
from arc.workflows import ForestSwarm, AgentTree

tree1 = AgentTree("analysis", agents=[analyzer, researcher])
tree2 = AgentTree("coding", agents=[coder, tester])

swarm = ForestSwarm(trees=[tree1, tree2], selector_llm=llm)
result = swarm.run(task)
```

### Hierarchical Swarm
Director-worker architecture with a director agent coordinating multiple worker agents.

```python
from arc.workflows import HierarchicalSwarm

swarm = HierarchicalSwarm(
    director_agent=director,
    worker_agents=[worker1, worker2, worker3]
)
result = swarm.run(task)
```

### Heavy Swarm
Five-phase comprehensive analysis with planning, parallel execution, review, revision, and synthesis.

```python
from arc.workflows import HeavySwarm

swarm = HeavySwarm(
    planner_agent=planner,
    worker_agents=[worker1, worker2],
    reviewer_agent=reviewer
)
result = swarm.run(task)
```

### Swarm Router
Universal workflow orchestrator that intelligently selects the best workflow pattern for each task.

```python
from arc.workflows import SwarmRouter

router = SwarmRouter(llm=llm)
router.register_workflow("sequential", sequential_workflow)
router.register_workflow("concurrent", concurrent_workflow)
router.register_workflow("mixture", mixture_workflow)

# Automatically selects best workflow
result = router.route_and_execute(task)
```

## Reinforcement Learning

Arc Framework includes built-in reinforcement learning capabilities that enable agents to learn from experience and continuously improve their tool selection and decision-making over time. The RL system uses Q-learning with semantic state representation to generalize across similar queries.

### Why Reinforcement Learning in Arc?

Traditional agent systems make the same tool selection decisions repeatedly, even when they fail. Arc's RL system learns from outcomes to:

- **Optimize Tool Selection**: Learn which tools work best for different query types
- **Reduce Costs**: Minimize unnecessary LLM calls by learning efficient tool sequences
- **Improve Over Time**: Continuously refine decision-making based on accumulated experience
- **Handle Ambiguity**: Make better choices when multiple tools could solve a task
- **Adapt to Domains**: Specialize to your specific use case and data

### Quick Start with RL

```python
from arc.agents import AgentFactory
from arc.rl import RLManager, HeuristicRewardCalculator
from langchain_core.tools import tool

# Define tools
@tool
def search(query: str) -> str:
    """Search for information."""
    return f"Results for: {query}"

@tool
def calculator(expression: str) -> str:
    """Calculate expression."""
    return str(eval(expression))

# Set up RL
tools = [search, calculator]
rl_manager = RLManager(
    tool_names=[t.name for t in tools],
    q_table_path="rl_data/q_table.pkl",
    exploration_rate=0.15,
    use_embeddings=True  # Semantic state matching
)

reward_calc = HeuristicRewardCalculator()

# Create RL-enabled agent
factory = AgentFactory(default_llm=llm)
agent = factory.create_react_agent(
    name="rl_agent",
    tools=tools,
    rl_enabled=True,
    rl_manager=rl_manager,
    reward_calculator=reward_calc
)

# Agent learns which tools work best!
result = agent.invoke({"messages": [("user", "What is 15 * 23?")]})
```

### Core RL Components

#### RLManager
The central RL controller that manages Q-tables, state encoding, and action selection.

```python
from arc.rl import RLManager

rl_manager = RLManager(
    tool_names=["search", "calculator", "database"],
    q_table_path="rl_data/q_table.pkl",
    learning_rate=0.1,           # How fast to update Q-values
    discount_factor=0.95,        # Future reward importance
    exploration_rate=0.15,       # Exploration vs exploitation
    exploration_decay=0.995,     # Reduce exploration over time
    min_exploration_rate=0.01,   # Minimum exploration to maintain
    use_embeddings=True,         # Semantic state matching
    embedding_model=embeddings   # For state representation
)
```

Key capabilities:
- **Q-Learning Algorithm**: Value-based RL for optimal action selection
- **State Representation**: Text queries converted to semantic embeddings
- **Exploration Strategy**: Epsilon-greedy with annealing
- **Persistent Learning**: Q-tables saved and loaded across sessions
- **Similarity Matching**: Generalize from similar past states

#### State Representation

Arc uses two state representation modes:

**Discrete States (use_embeddings=False)**:
- Direct string matching of queries
- Fast lookup, no embedding overhead
- Best for exact query repetition
- Limited generalization

**Semantic States (use_embeddings=True)**:
- Queries encoded as embeddings
- Matches semantically similar queries
- Better generalization to novel inputs
- Slightly higher computational cost

```python
# Semantic matching example
# "calculate 5+3" and "compute 5 plus 3" map to similar states
rl_manager = RLManager(
    tool_names=tools,
    use_embeddings=True,
    similarity_threshold=0.85  # How similar states must be to match
)
```

### Reward Calculators

Arc provides multiple reward calculation strategies:

#### Heuristic Rewards
Rule-based rewards for fast, deterministic evaluation.

```python
from arc.rl.rewards import HeuristicRewardCalculator

heuristic = HeuristicRewardCalculator(
    success_reward=1.0,        # Reward for successful tool use
    failure_reward=-0.5,       # Penalty for failures
    error_reward=-1.0,         # Penalty for errors/exceptions
    token_penalty=0.0001       # Small penalty for token usage (cost optimization)
)
```

Best for:
- Fast iteration during development
- Clear success/failure criteria
- Cost-sensitive applications

#### LLM-Based Rewards
LLM evaluates the quality of tool outputs.

```python
from arc.rl.rewards import LLMRewardCalculator

llm_reward = LLMRewardCalculator(
    llm=llm,
    evaluation_prompt="Rate the quality of this output on a scale of -1 to 1..."
)
```

Best for:
- Nuanced quality evaluation
- Subjective correctness
- Complex reasoning tasks

#### User Feedback Rewards
Human-in-the-loop learning.

```python
from arc.rl.rewards import UserFeedbackRewardCalculator

user_feedback = UserFeedbackRewardCalculator(
    feedback_prompt="Was this result helpful? (y/n): "
)
```

Best for:
- Critical applications
- Aligning with user preferences
- Fine-tuning after deployment

#### Composite Rewards
Combine multiple reward sources with weighted averaging.

```python
from arc.rl.rewards import CompositeRewardCalculator

composite = CompositeRewardCalculator([
    (heuristic, 0.4),      # 40% heuristic
    (llm_reward, 0.4),     # 40% LLM evaluation
    (user_feedback, 0.2)   # 20% user feedback
])
```

Best for:
- Balanced evaluation
- Production systems
- Multi-objective optimization

### RL Training Workflow

```python
from arc.rl import RLManager, HeuristicRewardCalculator
from arc.agents import AgentFactory

# 1. Initialize RL components
rl_manager = RLManager(
    tool_names=[t.name for t in tools],
    q_table_path="rl_data/q_table.pkl",
    exploration_rate=0.3,  # Start with high exploration
    use_embeddings=True
)

reward_calc = HeuristicRewardCalculator()

# 2. Create RL-enabled agent
agent = factory.create_react_agent(
    name="learning_agent",
    tools=tools,
    rl_enabled=True,
    rl_manager=rl_manager,
    reward_calculator=reward_calc
)

# 3. Training loop
training_queries = [
    "What is 5 * 10?",
    "Search for Python documentation",
    "Calculate 100 / 4",
    "Find information about LangChain"
]

for epoch in range(10):  # Multiple epochs
    for query in training_queries:
        result = agent.invoke({"messages": [("user", query)]})

    # Reduce exploration as training progresses
    rl_manager.decay_exploration()

    # Save Q-table periodically
    rl_manager.save_q_table()

print(f"Final exploration rate: {rl_manager.exploration_rate}")
```

### RL Features

- **Q-Learning Algorithm**: Value-based learning for optimal tool selection
- **Semantic State Matching**: Uses embeddings to generalize across similar queries
- **Flexible Reward Functions**: Heuristic, LLM-based, user feedback, or composite
- **Persistent Learning**: Q-tables automatically saved and loaded across runs
- **Exploration Annealing**: Gradually reduces exploration as agent gains experience
- **Action Masking**: Prevent selection of invalid or unavailable tools
- **Multi-Agent RL**: Different agents can share or maintain separate Q-tables
- **Transfer Learning**: Pre-trained Q-tables can be reused for similar tasks

### Advanced RL Patterns

#### Multi-Agent RL
Multiple agents learning independently or sharing knowledge.

```python
# Independent learning (separate Q-tables)
agent1 = factory.create_react_agent(
    name="agent1",
    tools=tools,
    rl_enabled=True,
    rl_manager=RLManager(tool_names=tool_names, q_table_path="agent1_q.pkl")
)

agent2 = factory.create_react_agent(
    name="agent2",
    tools=tools,
    rl_enabled=True,
    rl_manager=RLManager(tool_names=tool_names, q_table_path="agent2_q.pkl")
)

# Shared learning (same Q-table)
shared_rl = RLManager(tool_names=tool_names, q_table_path="shared_q.pkl")
agent1 = factory.create_react_agent(name="agent1", tools=tools,
                                    rl_enabled=True, rl_manager=shared_rl)
agent2 = factory.create_react_agent(name="agent2", tools=tools,
                                    rl_enabled=True, rl_manager=shared_rl)
```

#### Transfer Learning
Pre-train on one task, then fine-tune on another.

```python
# Pre-train on general queries
pretrain_rl = RLManager(tool_names=tool_names, q_table_path="pretrain_q.pkl")
# ... train on general queries ...

# Transfer to specialized domain
specialized_rl = RLManager(
    tool_names=tool_names,
    q_table_path="pretrain_q.pkl",  # Load pre-trained Q-table
    exploration_rate=0.1             # Lower exploration for fine-tuning
)
# ... train on specialized queries ...
```

#### Curriculum Learning
Gradually increase task difficulty.

```python
# Start with simple queries
simple_queries = ["Calculate 2+2", "Search for cats"]
# ... train ...

# Progress to medium complexity
medium_queries = ["What is the square root of 144?", "Search for Python asyncio docs"]
# ... train ...

# Finally, complex multi-step queries
complex_queries = ["Calculate the compound interest on $1000 at 5% for 10 years"]
# ... train ...
```

### When to Use RL

**Good Use Cases:**
- Agents with 5+ tools where selection is non-obvious
- Tasks with clear success/failure criteria
- Long-running agents that handle repeated query types
- Cost-sensitive applications (reduce unnecessary tool calls)
- Domains where optimal strategies aren't known upfront

**Not Recommended For:**
- Simple agents with 1-2 tools
- One-off queries with no repetition
- Tasks where correctness is critical and exploration is risky
- Real-time systems where inference speed is paramount

## Advanced Agent Patterns

Arc Framework supports sophisticated reasoning patterns for complex tasks.

### Self-Consistency Agent
Generates multiple reasoning paths and selects the most consistent answer.

```python
from arc.agents import SelfConsistencyAgent

agent = SelfConsistencyAgent(
    llm=llm,
    num_samples=5,
    temperature=0.7
)
result = agent.run("Complex reasoning task")
```

### Reflexion Agent
Iteratively refines outputs through self-reflection and learning from mistakes.

```python
from arc.agents import ReflexionAgent

agent = ReflexionAgent(
    llm=llm,
    max_iterations=3,
    reflection_prompt="Analyze your previous attempt..."
)
result = agent.run("Task requiring refinement")
```

### Reasoning Duo Agent
Uses two agents - one for reasoning and one for evaluation.

```python
from arc.agents import ReasoningDuoAgent

agent = ReasoningDuoAgent(
    reasoning_llm=llm,
    evaluation_llm=llm
)
result = agent.run("Complex problem")
```

### Agent Judge
Evaluates outputs from multiple agents and selects or combines the best.

```python
from arc.agents import AgentJudge

judge = AgentJudge(llm=llm)
best_output = judge.evaluate([output1, output2, output3])
```

### Agent Pattern Router
Automatically selects the best agent pattern for each task.

```python
from arc.agents import AgentPatternRouter, AgentPattern, create_agent

# Create agents with different patterns
react_agent = create_agent(
    pattern=AgentPattern.REACT,
    llm=llm,
    tools=tools
)

reflexion_agent = create_agent(
    pattern=AgentPattern.REFLEXION,
    llm=llm,
    tools=tools
)

# Router selects best pattern
router = AgentPatternRouter(llm=llm)
router.register_agent(AgentPattern.REACT, react_agent)
router.register_agent(AgentPattern.REFLEXION, reflexion_agent)

result = router.route_and_execute(task)
```

```python
from arc.agents import MCPTeamBuilder

mcp_team = (MCPTeamBuilder("research_team")
```

### Error Handling & Validation

Comprehensive error handling with custom exception hierarchy:

```python
from arc.exceptions import (
    ConfigurationError,
    ValidationError,
    LLMTimeoutError,
    NodeExecutionError,
    GraphCycleError,
```
