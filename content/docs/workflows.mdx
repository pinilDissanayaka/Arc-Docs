### 1.1 Self-Consistency Pattern

**When to use:**
- Questions with multiple possible solutions
- Need high confidence in answers
- Acceptable latency for multiple LLM calls

**How it works:**
1. Generate N independent solutions
2. Use majority voting to select best answer
3. Optionally use LLM to aggregate and explain

**Implementation:**

```python
from arc.agents import create_agent
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini")

# Create self-consistency agent
sc_agent = create_agent(
    pattern="self-consistency",
    llm=llm,
    tools=[],
    num_samples=5,  # Generate 5 independent answers
    majority_voting_prompt="Analyze these answers and pick the best one"
)

# Use for questions with multiple solution paths
result = sc_agent.invoke({
    "messages": [("user", "If I have 3 apples and buy 2 more, then give away 1, how many do I have?")]
})

# Agent generates 5 solutions and picks most common answer
print(result["messages"][-1].content)
```

**Advanced Configuration:**

```python
# Custom aggregation
sc_agent = create_agent(
    pattern="self-consistency",
    llm=llm,
    num_samples=7,  # More samples for higher confidence
    majority_voting_prompt="""
    Analyze these solutions:
    1. Check mathematical correctness
    2. Identify common answer
    3. Explain why that answer is correct
    4. Note any edge cases
    """
)

# Use with tools
from langchain_core.tools import tool

@tool
def calculator(expr: str) -> str:
    """Calculate expression."""
    return str(eval(expr))

sc_agent_with_tools = create_agent(
    pattern="self-consistency",
    llm=llm,
    tools=[calculator],
    num_samples=5
)
```

**Best Practices:**
- Use 5-7 samples for balance of accuracy and latency
- Great for mathematical reasoning
- Combine with tools for fact-checking
- Use stronger LLM for aggregation (e.g., GPT-4 for samples, GPT-4o for voting)

### 1.2 Reflexion Pattern

**When to use:**
- Complex reasoning tasks
- Iterative improvement needed
- Quality more important than speed

**How it works:**
1. **Act**: Generate initial response
2. **Evaluate**: Score quality (0-10)
3. **Reflect**: Identify improvements
4. **Refine**: Generate improved response
5. **Repeat**: Until quality threshold or max loops

**Implementation:**

```python
from arc.agents import create_agent

# Create reflexion agent
reflexion_agent = create_agent(
    pattern="reflexion",
    llm=llm,
    tools=[search_tool],
    max_loops=3,          # Max reflection iterations
    memory_capacity=100   # Memory size for past reflections
)

# Use for complex reasoning
result = reflexion_agent.invoke({
    "messages": [("user", "Explain the implications of quantum computing on current encryption")]
})

# Process:
# Loop 1: Initial answer (score: 6/10)
# Loop 2: Reflect on gaps, generate improved answer (score: 8/10)
# Loop 3: Final refinement (score: 9/10)
print(result["messages"][-1].content)
```

**Advanced Configuration:**

```python
# With custom evaluation criteria
reflexion_agent = create_agent(
    pattern="reflexion",
    llm=llm,
    tools=[search, database],
    max_loops=5,
    memory_capacity=200,
    evaluation_criteria=[
        "Technical accuracy",
        "Completeness of explanation",
        "Clarity for target audience",
        "Use of concrete examples",
        "Addressing counterarguments"
    ]
)

# Early stopping based on quality
reflexion_agent = create_agent(
    pattern="reflexion",
    llm=llm,
    tools=[],
    max_loops=10,
    quality_threshold=9.0,  # Stop when score >= 9.0
    memory_capacity=100
)
```

**Memory System:**

```python
# Reflexion maintains short-term and long-term memory

# Short-term: Current task reflections
# Long-term: Past successful approaches

# Memory is automatically used to:
# 1. Avoid repeating mistakes
# 2. Apply successful patterns
# 3. Build on previous insights
```

**Best Practices:**
- Start with max_loops=3 for balance
- Use quality_threshold for early stopping
- Provide clear evaluation criteria
- Monitor memory usage for long-running agents
- Great for essays, reports, complex analyses

### 1.4 Agent Judge Pattern

**When to use:**
- Need to evaluate agent outputs
- Quality assurance required
- A/B testing different approaches

**How it works:**
1. Receives output to evaluate
2. Scores against criteria
3. Provides detailed feedback
4. Returns numeric score + explanation

**Implementation:**

```python
from arc.agents import create_agent

# Create judge
judge = create_agent(
    pattern="agent-judge",
    llm=llm,
    evaluation_criteria=[
        "Accuracy",
        "Completeness",
        "Clarity",
        "Relevance",
        "Actionability"
    ],
    return_score=True
)

# Evaluate an agent's output
question = "What is photosynthesis?"
answer = "Photosynthesis is how plants make food using sunlight."

result = judge.invoke({
    "messages": [
        ("user", question),
        ("assistant", answer)
    ]
})

evaluation = result["evaluation"]
score = result["score"]  # 0-10

print(f"Score: {score}/10")
print(f"Feedback: {evaluation}")
```

**Advanced Configuration:**

```python
# Weighted criteria
judge = create_agent(
    pattern="agent-judge",
    llm=llm,
    evaluation_criteria={
        "Technical Accuracy": 0.4,
        "Clarity": 0.3,
        "Completeness": 0.2,
        "Practicality": 0.1
    },
    return_score=True,
    score_range=(0, 100)  # Custom range
)

# Domain-specific evaluation
code_judge = create_agent(
    pattern="agent-judge",
    llm=llm,
    evaluation_criteria=[
        "Code correctness",
        "Efficiency",
        "Readability",
        "Best practices",
        "Security considerations"
    ]
)

# Batch evaluation
results = []
for question, answer in test_cases:
    eval_result = judge.invoke({
        "messages": [("user", question), ("assistant", answer)]
    })
    results.append(eval_result)

avg_score = sum(r["score"] for r in results) / len(results)
```

**Best Practices:**
- Use for quality assurance pipelines
- Great for A/B testing agents
- Provide clear, measurable criteria
- Use weighted criteria for priorities
- Consider using GPT-4 for more reliable evaluation

### 1.5 Combining Patterns

**Reflexion + Self-Consistency:**

```python
# Generate multiple solutions with iterative refinement
def reflexion_with_consistency(query: str, llm, tools, num_samples=3, max_loops=2):
    """
    Combine reflexion and self-consistency.

    Process:
    1. Use reflexion to generate refined answer
    2. Use self-consistency to verify
    """

    # Step 1: Reflexion for quality
    reflexion_agent = create_agent(
        pattern="reflexion",
        llm=llm,
        tools=tools,
        max_loops=max_loops
    )

    refined = reflexion_agent.invoke({
        "messages": [("user", query)]
    })

    # Step 2: Self-consistency for validation
    sc_agent = create_agent(
        pattern="self-consistency",
        llm=llm,
        num_samples=num_samples
    )

    validated = sc_agent.invoke({
        "messages": [("user", query)]
    })

    # Step 3: Compare and synthesize
    judge = create_agent(pattern="agent-judge", llm=llm)

    comparison = judge.invoke({
        "messages": [
            ("user", f"Question: {query}"),
            ("assistant", f"Reflexion answer: {refined['messages'][-1].content}"),
            ("assistant", f"Consistency answer: {validated['messages'][-1].content}")
        ]
    })

    return comparison
```

**Reasoning Duo + Judge:**

```python
# Strategic decision with evaluation
def strategic_decision_with_review(query: str, llm):
    """
    Make strategic decision with quality review.
    """

    # Step 1: Deep reasoning
    duo = create_agent(pattern="reasoning-duo", llm=llm)
    decision = duo.invoke({"messages": [("user", query)]})

    # Step 2: Evaluate decision quality
    judge = create_agent(
        pattern="agent-judge",
        llm=llm,
        evaluation_criteria=[
            "Strategic alignment",
            "Risk assessment",
            "Feasibility",
            "Expected impact"
        ]
    )

    evaluation = judge.invoke({
        "messages": decision["messages"]
    })

    # Step 3: Refine if score low
    if evaluation["score"] < 7:
        # Use reflexion to improve
        reflexion = create_agent(pattern="reflexion", llm=llm, max_loops=2)
        improved = reflexion.invoke({"messages": [("user", query)]})
        return improved

    return decision
```

### 2.1 Hierarchical Delegation Pattern

**When to use:**
- Complex multi-step workflows
- Need coordination between teams
- Dynamic task routing

**Implementation:**

```python
from arc import (
    GraphOrchestrator,
    CoordinatorNode,
    PlannerNode,
    ResponseGeneratorNode
)
from arc.core import Supervisor
from arc.agents import TeamBuilder

# Create specialized teams
research_team = (TeamBuilder("research")
    .with_llm(llm)
    .with_tools([search, scrape, analyze])
    .with_prompt("Research specialist")
    .build())

writing_team = (TeamBuilder("writing")
    .with_llm(llm)
    .with_tools([generate_report, format_doc])
    .with_prompt("Writing specialist")
    .build())

review_team = (TeamBuilder("review")
    .with_llm(llm)
    .with_tools([grammar_check, fact_check])
    .with_prompt("Review specialist")
    .build())

# Create supervisor
supervisor = Supervisor(
    llm=llm,
    members=["research", "writing", "review"]
)

# Build hierarchical graph
orchestrator = GraphOrchestrator()
graph = orchestrator.build_hierarchical_graph(
    coordinator=CoordinatorNode(llm),
    planner=PlannerNode(llm),
    supervisor=supervisor,
    teams=[research_team, writing_team, review_team],
    generator=ResponseGeneratorNode(llm)
)

# Run complex workflow
result = graph.invoke({
    "messages": [{
        "role": "user",
        "content": "Research AI ethics, write a report, and review for accuracy"
    }]
})
```

### 2.4 Dynamic Routing Pattern

**When to use:**
- Request type determines workflow
- Need flexible routing
- Different complexity levels

**Implementation:**

```python
from arc.agents import AgentRouter, HandoffAgent

# Create specialist agents
quick_agent = factory.create_react_agent("quick", [calculator])
standard_agent = factory.create_react_agent("standard", [search, calculator])
complex_agent = create_agent("reflexion", llm, [search, analyze], max_loops=3)

# Create router
router = AgentRouter(llm)
router.add_agent(quick_agent)
router.add_agent(standard_agent)
router.add_agent(complex_agent)

# Create coordinator with handoff
coordinator = HandoffAgent(
    name="coordinator",
    llm=llm,
    router=router,
    routing_prompt="""
    Analyze request complexity:
    - Simple calculation → quick
    - Standard query → standard
    - Complex reasoning → complex
    """
)

# Dynamic routing based on request
simple_result = coordinator.invoke({
    "messages": [("user", "What is 2+2?")]
})  # Routes to quick_agent

complex_result = coordinator.invoke({
    "messages": [("user", "Explain quantum entanglement and its implications")]
})  # Routes to complex_agent
```

### 3.1 Basic RL Pattern

**When to use:**
- Multiple tools available
- Want agent to learn optimal selection
- Have reward signal

**Implementation:**

```python
from arc.rl import RLManager, HeuristicRewardCalculator
from arc.agents import AgentFactory

# Setup RL
tools = [search, calculator, database, api_call]
rl_manager = RLManager(
    tool_names=[t.name for t in tools],
    q_table_path="rl_data/q_table.pkl",
    exploration_rate=0.15,
    use_embeddings=True
)

reward_calc = HeuristicRewardCalculator()

# Create RL-enabled agent
factory = AgentFactory(default_llm=llm)
agent = factory.create_react_agent(
    name="rl_agent",
    tools=tools,
    rl_enabled=True,
    rl_manager=rl_manager,
    reward_calculator=reward_calc
)

# Agent learns over time which tools work best
for query in training_queries:
    result = agent.invoke({"messages": [("user", query)]})
    print(f"Query: {query}")
    print(f"Tools used: {result.get('rl_metadata', {}).get('selected_tools', [])}")

# Check learning progress
stats = rl_manager.get_statistics()
print(f"Total states: {stats['total_states']}")
print(f"Avg Q-value: {stats['avg_q_value']:.2f}")
```

### 3.3 Exploration Strategy Patterns

**Epsilon-Greedy (Default):**

```python
# Good for: General purpose, balanced exploration
rl_manager = RLManager(
    tool_names=tools,
    exploration_rate=0.15,
    exploration_strategy=ExplorationStrategy.EPSILON_GREEDY
)

# Gradually reduce exploration
for episode in range(num_episodes):
    # Run episode
    result = agent.invoke(state)

    # Anneal exploration
    if episode % 10 == 0:
        rl_manager.anneal_exploration(decay_rate=0.95)
```

**Upper Confidence Bound (UCB):**

```python
# Good for: Systematic exploration, fewer tools
rl_manager = RLManager(
    tool_names=tools,
    exploration_strategy=ExplorationStrategy.UCB,
    ucb_c=2.0  # Exploration parameter
)

# UCB automatically balances:
# - Tools with high Q-values (exploitation)
# - Tools tried less often (exploration)
```

**Thompson Sampling:**

```python
# Good for: Bayesian approach, uncertainty quantification
rl_manager = RLManager(
    tool_names=tools,
    exploration_strategy=ExplorationStrategy.THOMPSON_SAMPLING
)

# Samples from belief distributions
# More sophisticated than epsilon-greedy
```

**Epsilon Decay:**

```python
# Good for: Automatic annealing, long training
rl_manager = RLManager(
    tool_names=tools,
    exploration_strategy=ExplorationStrategy.EPSILON_DECAY,
    exploration_rate=0.3,  # Start high
    decay_rate=0.995       # Gradual decay
)

# Exploration automatically decreases over time
# No manual annealing needed
```

### 3.4 Transfer Learning Pattern

**When to use:**
- Multiple similar agents
- Want to share learning
- Bootstrap new agents

**Implementation:**

```python
# Train base agent
base_rl = RLManager(
    tool_names=["search", "calculator", "database"],

    name="base_agent",

    base_agent.invoke({"messages": [("user", query)]})

# Create specialized agent with transferred knowledge
specialized_rl = RLManager(
    tool_names=["search", "calculator", "database", "specialized_tool"],
    q_table_path="rl_data/base_q_table.pkl",  # Load base knowledge
    use_embeddings=True

    name="specialized_agent",
    tools=[search, calculator, database, specialized_tool],
    rl_enabled=True,
    rl_manager=specialized_rl
)

# Specialized agent starts with base knowledge
# Continues learning for specialized task
```

### 4.3 MCP with RL Pattern

**When to use:**
- Many MCP tools available
- Want to learn optimal MCP tool selection
- Performance optimization needed

**Implementation:**

```python
from arc.rl import RLManager, HeuristicRewardCalculator

# Fetch MCP tools first
mcp_builder = MCPTeamBuilder("mcp_team")
mcp_builder.with_llm(llm)
mcp_builder.with_mcp_server("python", ["server1.py"])
mcp_builder.with_mcp_server("python", ["server2.py"])

mcp_tools = mcp_builder.get_mcp_tools()

# Setup RL for MCP tools
rl_manager = RLManager(
    tool_names=[t.name for t in mcp_tools],
    q_table_path="rl_data/mcp_q_table.pkl",
    exploration_rate=0.15,
    use_embeddings=True
)

reward_calc = HeuristicRewardCalculator()

# Create RL-enabled MCP team
mcp_rl_team = (mcp_builder
```

## 7. Error Handling and Recovery

### 5.1 Graceful Degradation Pattern

**Implementation:**

```python
from arc.exceptions import (
    NodeExecutionError,
    ToolExecutionError,
    LLMTimeoutError
)

def execute_with_fallback(graph, query, fallback_response):
    """Execute with graceful degradation."""

    try:
        # Try primary execution
        result = graph.invoke({
            "messages": [{"role": "user", "content": query}]
        })
        return result["messages"][-1].content

    except LLMTimeoutError:
        logger.warning("LLM timeout, using cached response")
        cached = cache.get(query)
        if cached:
            return cached
        return fallback_response

    except ToolExecutionError as e:
        logger.error(f"Tool failed: {e}")
        # Retry without failed tool
        simplified_graph = rebuild_graph_without_tool(e.details["tool_name"])
        result = simplified_graph.invoke({
            "messages": [{"role": "user", "content": query}]
        })
        return result["messages"][-1].content

    except NodeExecutionError as e:
        logger.error(f"Node failed: {e}")
        # Skip failed node if possible
        if e.details["node_name"] == "optional_node":
            modified_graph = rebuild_graph_skip_node(e.details["node_name"])
            result = modified_graph.invoke({
                "messages": [{"role": "user", "content": query}]
            })
            return result["messages"][-1].content
        return fallback_response

    except Exception as e:
        logger.exception(f"Unexpected error: {e}")
        return fallback_response
```

```python
def retry_with_jitter(func, max_retries=3):
    """Retry with exponential backoff and jitter."""

    for attempt in range(max_retries):
        try:
            return func()
        except Exception as e:
            if attempt == max_retries - 1:
                raise

            # Exponential backoff with jitter
            base_delay = 2 ** attempt
            jitter = random.uniform(0, 1)
```

### 5.3 Circuit Breaker Pattern

**Implementation:**

```python
from enum import Enum
from datetime import datetime, timedelta

class CircuitState(Enum):
    CLOSED = "closed"    # Normal operation
    OPEN = "open"        # Failures threshold exceeded
    HALF_OPEN = "half_open"  # Testing if recovered

class CircuitBreaker:
    """Circuit breaker for external services."""

    def __init__(
        self,
        failure_threshold: int = 5,
        timeout: int = 60,
        recovery_timeout: int = 30
    ):
        self.failure_threshold = failure_threshold
        self.timeout = timeout
        self.recovery_timeout = recovery_timeout

        self.failure_count = 0
        self.last_failure_time = None
        self.state = CircuitState.CLOSED

    def call(self, func, *args, **kwargs):
        """Execute function with circuit breaker."""

        if self.state == CircuitState.OPEN:
            if self._should_attempt_reset():
                self.state = CircuitState.HALF_OPEN
            else:
                raise Exception("Circuit breaker is OPEN")

        try:
            result = func(*args, **kwargs)
            self._on_success()
            return result

        except Exception as e:
            self._on_failure()
            raise

    def _on_success(self):
        """Handle successful call."""
        self.failure_count = 0
        self.state = CircuitState.CLOSED

    def _on_failure(self):
        """Handle failed call."""
        self.failure_count += 1
        self.last_failure_time = datetime.now()

        if self.failure_count >= self.failure_threshold:
            self.state = CircuitState.OPEN
            logger.warning("Circuit breaker opened")

    def _should_attempt_reset(self):
        """Check if should attempt reset."""
        if self.last_failure_time is None:
            return True

        elapsed = (datetime.now() - self.last_failure_time).total_seconds()
        return elapsed >= self.recovery_timeout

# Usage
mcp_circuit_breaker = CircuitBreaker(
    failure_threshold=3,
    recovery_timeout=60
)

def call_mcp_with_circuit_breaker(mcp_tool, query):
    """Call MCP tool with circuit breaker."""
    return mcp_circuit_breaker.call(mcp_tool.invoke, query)
```

```python
def batch_process(agent, queries: List[str], batch_size: int = 10):
    """Process queries in batches."""

    results = []
    for i in range(0, len(queries), batch_size):
        batch = queries[i:i + batch_size]

        batch_results = []
        for query in batch:
            result = agent.invoke({"messages": [("user", query)]})
            batch_results.append(result)

        results.extend(batch_results)

        # Optional: Add delay between batches to avoid rate limits
        if i + batch_size < len(queries):
            time.sleep(1)

    return results
```

```python
    active_requests.inc()

        result = graph.invoke({
            "messages": [{"role": "user", "content": query}]
```
